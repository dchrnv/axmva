# Истина vs производное (решение, 2026-10-31)

Источник: раздел «Истина и производное» в `/home/assis/Загрузки/axmg-blueprint.md` (чертёж владельца «axmg с нуля»). Записано как Шаг 3 Фазы 3 `ROADMAP.md` — решение нужно до Шага 4 (тег источника), Шага 5 (persist) и Шага 6 (Port): оба спрашивают «что мы обязаны сохранить/пропустить через единую дверь», и ответ на это — здесь.

## Определение (из чертежа, принято без изменений)

Истина — то, из чего всё остальное восстанавливается детерминированно, и только оно хранится как история (append-only). Производное — пересобирается из истины; его потеря или обрезка стоит только времени пересборки, не памяти.

## Что в axmva уже истина (де-факто, без переоформления)

1. **Тела токенов Store** (`level`, `children`, в порядке рождения) — неизменимы с рождения (I ядра), уже персистятся (`elements/persist::save`/`save_all`).
2. **Append-only лог Focus/Unfocus** (`elements/death::DeathLog::events`) — уже персистится. Формально это производное (пересчитывается из Store+epoch+ppmi через `mark`/`weight_cut`), но решено хранить его как истину напрямую — пересчёт с нуля требует повторного прогона PPMI по всей истории при каждой загрузке, а сам лог append-only и маленький. Осознанный компромисс, не пересматривается этим решением.

## Что сейчас производное, но НЕ персистится вообще (реальный пробел, не просто классификация)

- `epoch.sequence`, `epoch.revolution`, `epoch.last_touched_revolution` — после перезапуска процесса просто пропадают. Пересобрать их можно только полным повторным `epoch.run_corpus()` на ВСЕХ входных байтах с самого начала — а входные байты (порции с тегом источника и номером оборота) сейчас тоже не персистятся. Получается дыра: производное не сохранено, и истина, из которой его можно было бы пересобрать, тоже не сохранена.
- PPMI CSR/`CooAccumulator` — пересчитывается с нуля из `sequence` при каждом вызове уже сейчас (ни один элемент не хранит его между вызовами) — архитектурно это уже "производное" в духе чертежа, вопрос только в источнике (`sequence`), которого после перезапуска не будет.
- `clock`/`axtime::Time<TokenId>` (`TouchLog`, `GrowthSeries`, `OccurrenceLog`) — живёт только в памяти процесса `Clock`, пересобирается проигрыванием потока оборотов через `Clock::turn()`.
- `axaxes` классификация — пересчитывается из измерений каждый раз, не хранится отдельно.

## Решение

1. **Новая истина (Шаг 4, пока не реализован): append-only поток входных порций.** Каждая запись: номер оборота, тег источника (кто подал: корпус/папка `input/`, диалог, сенсор — см. `elements/external-input`), сырые байты порции. Это и закрывает открытый вопрос «тег источника» (deck-map, п. «Вход: от корпуса к первому циклу»), и даёт честный источник для полной пересборки с нуля.
2. **persist (Шаг 5) хранит и истину, и явный кэш дорогого производного — не одно вместо другого.** Чертёж допускает кэш явно («Кэш и снапшоты: чтобы не пересобирать при каждом старте»). Конкретно:
   - Поток порций (новая истина) — обязателен, иначе полная пересборка в принципе невозможна.
   - `sequence`/`revolution`/`last_touched_revolution` — кэшируются явно, НЕ только пересчитываются из потока порций при каждой загрузке. Причина — измерено: стоимость `epoch.turn()` без лимита растёт квадратично с суммарной длиной потока (`tools/epoch-cost-bench`, см. `elements/epoch/passport.yaml`) — полная пересборка проигрыванием потока порций на реальном масштабе дорога, не бесплатна.
   - PPMI/cooc, `clock`/axtime-состояние, `axaxes`-классификация — НЕ кэшируются отдельно, пересчитываются на лету после загрузки из закэшированного `sequence`. Дешевле, чем `epoch.turn()` (один проход `Window::extract` + `CooAccumulator`, не каскад слияний), и это уже их нынешнее поведение внутри одного процесса — ничего нового для них не нужно, кроме живого `sequence`.
3. **Приёмочный критерий чертежа** («пересобранное проигрыванием потоков совпадает по хэшу с живым состоянием») становится реальным тестом только после Шага 4 (поток порций существует) — до этого физически нечем проверять. Формулировка на будущее: `epoch`, полностью пересобранный проигрыванием сохранённого потока порций через `run_corpus`, даёт побитово тот же `Store`/`sequence`/`last_touched_revolution`, что и живое состояние до сохранения (детерминизм уже доказан отдельно, см. `tools/compare-axmg` — здесь проверяется не детерминизм слияния, а полнота сохранённого потока).

## Что это меняет в плане (Шаги 4-5 Фазы 3 `ROADMAP.md`)

- Шаг 4 (тег источника): тег — часть НОВОЙ истины (поток порций), не отдельная колонка на токене сама по себе. Колонка «число разных источников на токен» — производное, считается при проигрывании потока порций (каждая порция в своём обороте касается каких-то токенов — считаем разные теги на токен).
- Шаг 5 (persist): добавить таблицу потока порций (истина) + явный кэш `sequence`/`revolution`/`last_touched_revolution` (производное, но дорогое для пересборки). PPMI/clock/axaxes не персистятся — пересчитываются после загрузки из кэшированного `sequence`, как и сейчас внутри одного процесса.
