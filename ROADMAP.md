## Фаза 1 — Первые элементы (сделано, 2026-10-26 — 2026-10-28)

Девять элементов, все `status: hypothesis` (checks.yaml не писали — I27, это твой шаг):

- `core` — байты → примитивы, слияние, неизменимое хранение. Код + 13 тестов.
- `external-input` — контракт входа (порция + тег источника); физическая реализация — `input/`.
- `epoch` — оборот как единица времени, накопленная последовательность. Код + 4 теста.
- `death` — mark (достижимость, K=3) + weight_cut (срез по весу PPMI). Код + 7 тестов.
- `surprise` (Отшельник) — S-static/S-growth, диагностика. Код + 5 тестов.
- `ppmi` — перевёрнутая библиотека, со-встречаемость + значимость связи. Код + 10 тестов.
- `persist` — redb, тело Store + лог Смерти в одной ACID-транзакции. Код + 5 тестов.
- `time` (пакет **`axtime`**) — вынесен в отдельный публичный репозиторий [github.com/dchrnv/axtime](https://github.com/dchrnv/axtime) (MIT OR Apache-2.0): полностью обобщённая библиотека, не привязана к токенам, все 4 вида v1 (stamp/age/age_inner/period) плюс настенное время реальны и протестированы (11/11). В этом репозитории остался только паспорт; код подключается path-зависимостью, как `axmg`. Интеграция с доменом — формальный элемент `elements/clock` (см. 0.4.3).
- `axes` (стихии, пакет **`axaxes`**) — обобщённая библиотека готова и протестирована (15/15): выбор пары мер по балансу/независимости, бинаризация с гистерезисом, классификация в 4 клетки, матрица взаимодействий. Пока внутри этого репозитория (не вынесена отдельно, как axtime). Прогнана на реальных данных через `tools/axes-integration-demo`: пул из предложенных черновиком мер (частота, разнообразие контекстов) ОТКАЗАН на двух файлах — меры коррелируют (MI 0.56-0.60 бит, порог 0.1), баланс далеко от 50/50. Отказ — правильное поведение механизма, не баг; нужны другие меры-кандидаты.

Плюс `tools/compare-axmg` — параллельная проверка против референса на реальных файлах: на входе короче 100 000 токенов в свёртке совпадает побитово со всем, что мы прогоняли; на длинных файлах расходится предсказуемо (см. ниже).

**Библиотека, не монолит.** По цели пользователя (2026-10-28): собираем всё подобно `axmg` — как библиотеку, которую можно подключать, но части, которые не завязаны на токены/Store, выделяются в свои обобщённые крейты (`axtime` готов, `axaxes` следующий), а не остаются внутренними модулями конкретного движка. `wheel` переименован в `epoch` (это цикл-функция шага, не отдельная подсистема).

## Фаза 3 — Ремонт по чертежу axmg (2026-10-31, не решено, но упорядочено по зависимостям)

Источник: `/home/assis/Загрузки/axmg-blueprint.md` (чертёж владельца «axmg с нуля», черновик 1, 2026-10-30), сверен с реальным кодом axmva тем же днём — каждая находка подтверждена чтением кода (`grep`/прямое чтение), не предположением. Полный список находок (с чем уже всё в порядке и что реально не починено) — в истории чата 2026-10-30/31, здесь только план починки, по шагам, в порядке зависимостей (каждый следующий шаг использует решение предыдущего, по возможности не раньше).

1. **[x] Без паник в библиотечном коде (инвариант 5 чертежа).** Сделано 2026-10-31.
   - `elements/persist` — `decode_event` паниковал на неизвестный байт типа записи → теперь `LoadError::CorruptEventKind`, новый тест. 8/8 → 9/9, версия 0.2.0 → 0.3.0.
   - `elements/axes/src/measure.rs` — `median()` паниковал на NaN (`.expect(...)`) → `f64::total_cmp`, сигнатура не изменилась, версия 0.2.0 → 0.2.1.
   - `elements/death/src/lib.rs` — сортировка `weight_cut` по весу паниковала на NaN (`.unwrap()` на `partial_cmp`) → `f64::total_cmp`, версия 0.1.0 → 0.1.1.
   - `elements/ppmi/src/cooc.rs` — структурно безопасный, но всё же panic-путь `.expect(...)` в `bake_to_csr()` убран целиком (переписано без промежуточного `remove`), версия 0.1.0 → 0.1.1.
   - Полный прогон по всем 9 крейтам без регрессий.
2. **Независимые измерения (дёшево, без зависимостей, информируют остальные шаги).**
   - Измерить K=3/квантиль 25% (`elements/death`, `weight_cut`) на СВОИХ данных — сейчас цифра «13–23% сжатия» в документах принадлежит измерению axmg на их корпусе ("Гит"), не воспроизведена нами ([death/passport.yaml:87](elements/death/passport.yaml:87) сам это признаёт).
   - Добавить количественный контроль "S-static реальный текст vs перетасованный" для `elements/surprise`, по методу `ppmi_demo.rs`'s shuffle-control — сейчас `surprise_demo.rs` только качественно сравнивает "знакомое vs тарабарщина", без цифры и без перетасовки.
3. **Истина vs производное — архитектурное решение (перед Port и persist, см. раздел чертежа «Истина и производное»).**
   - Решить и записать (в `Invariants.md` или отдельный draft): что в axmva — истина (append-only: тела токенов + поток порций с тегом источника и номером оборота) и что — производное (пересобираемое: counts, `last_touched`, PPMI-связи, фокус).
   - Решить: persist хранит только истину и пересобирает производное при загрузке, или кэширует производное отдельно как оптимизацию — по замеру стоимости пересборки, не по умозрительному выбору.
4. **Тег источника (зависит от Шага 3 — тег это часть истины).**
   - Провести тег порции через приём: `epoch::turn`/`run_corpus` (или новая обёртка) должны принимать и хранить тег, не только байты — `elements/external-input` сейчас только паспорт-прокси (`ingest_bytes_tagged` упомянут как "уже в axmg", у нас не реализован).
   - Добавить колонку «число разных источников» на токен — нужна карте Звезда (уже отмечена как открытый вопрос в паспортах `epoch`/`time`/`recall`).
5. **persist сохраняет достаточно для честного restart (зависит от Шагов 3–4).**
   - Расширить `save`/`save_all`: по решению Шага 3 сохранить либо саму истину (тела + поток порций с тегами), либо достаточно производного для пересборки (`sequence`, `revolution`, `last_touched_revolution`, PPMI-счётчики).
   - Добавить приёмочный тест прямо из чертежа (раздел 8): перезагрузка с диска даёт тот же `recall()` и тот же вердикт `check_surprise`, что и до сохранения. Сейчас это физически не может пройти — `sequence` не персистится.
6. **Единая дверь: Port/PortSnapshot/Moderator (зависит от Шагов 3–5).**
   - Спроектировать и реализовать единственную точку доступа между ядром и остальными элементами: read-only снапшот для чтения, один приёмный метод для записи — закрывает и старый пункт «Сборка» Фазы 2.
   - Правило чертежа: новый метод порта добавляется только вместе с потребителем и строкой в паспорте — перенести как процессное правило, не только как код.
7. **Бюджет роста PPMI-связей (можно параллельно с Шагом 6, не зависит от Port).**
   - По методологии `max_sequence_len` у `epoch` (измерить, не скопировать число у axmg): добавить top-k соседей по PPMI на узел и/или затухание веса по обороту и/или общий бюджет рёбер. Конкретный механизм — по замеру на реальных данных, не наугад. Сейчас `CooAccumulator`/`Csr` растут без потолка — ровно то, что владелец axmg называет «слабым местом» черновика.
8. **Умеренность — новый элемент (низкий приоритет, не блокирует остальное).**
   - Перенос «горячих» счётчиков сессии в «холодный» файл весов по пропорции α (черновик уже есть в `drafts/axmv2-deck-map.md`, карта 14) — элемента пока нет вообще, ни кода, ни паспорта.

- 0.4.1 (2026-10-29): исправлен реальный баг в `persist`, найденный вручным прогоном (не чтением кода) — `save`/`save_all` сверяли только длину уже сохранённой таблицы, не её содержимое; несвязанный `Store` короче уже записанного тихо «сохранялся» без единой новой записи (`Ok(())`, файл не менялся). Теперь обе функции сверяют весь уже сохранённый префикс (тела + события) и возвращают `SaveError` при расхождении. 3 новых регрессионных теста, персист: 5→8.
- 0.4.2 (2026-10-29): окно последовательности `epoch` решено — измерили (`tools/epoch-cost-bench` на Carlsen.pgn, 88 оборотов) реальную стоимость оборота: без лимита растёт линейно от длины `sequence` (~0.00035 мс/элемент после прогрева), суммарно по всем оборотам квадратично от размера непрерывного потока; не проблема на файлах в единицы МБ (~10 сек), стала бы проблемой на многодневном потоке. Добавили `EpochState::with_max_sequence_len(max)` — явный, опциональный (по умолчанию без ограничения, старое поведение не изменилось), число не скопировано у axmg, а выводится из бюджета времени на оборот. С лимитом 50000 время на оборот стабилизируется на ~35-40 мс (было до ~270 мс без лимита). 4 новых теста, epoch: 4→8.
- 0.4.3 (2026-10-29): `elements/clock` — формальный мост между `epoch`, `surprise` и `axtime`: один оборот часов = `s_growth` на замороженном (до слияния) Store этого чанка + `epoch.turn()` + реальные касания, переданные в `axtime::Time<TokenId>`. Все 4 вида времени v1 теперь настоящие для токенов, не только демонстрационные. `tools/time-integration-demo` удалён как дубль (не формальный элемент, без паспорта). 5 новых тестов (clock: 0→5); полный прогон по всем крейтам (65 тестов) без регрессий.
