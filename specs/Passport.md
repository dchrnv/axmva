# Passport v0.2

Passport это описание элемента: кто он, что обещает, с кем связан, что читает модель. Один файл на элемент, лежит рядом с ним. Имена и неизменяемые правила: [[Invariants]]. Как писать passport по шагам: [[Passport-guide]]. Нерешённые вопросы: [[Deferred]]. Эта версия самодостаточна: включает всё, что было раньше.

## 1. Файлы

```
<элемент>/
  passport.yaml    # схема элемента. Хешируется
  checks.yaml      # результаты проверок. Не хешируется, ссылается на element_hash. Агенты не пишут (I27)
<корень сборки>/
  passport.yaml    # passport сборки (kind: assembly)
  index.yaml       # генерируется сканом, руками не правится
```

Формат: YAML. В Обсидиане допустима заметка `passport.md` с YAML-блоком. Для MCP часть `for_model` выгружается в JSON. `id` в файле не пишется: он выводится из пути к элементу.

## 2. Passport элемента

Обязательные для всех: `kind`, `status`, `version`, `role`. `inputs` и `outputs` обязательны, если `status: done`; для остальных необязательны (так стаб из одного `kind/status/role` остаётся допустимым).

```yaml
passport_schema: "0.2"
kind: code               # * code | model | data | external | assembly
status: done             # * done | hypothesis | analogy | fantasy
version: 0.1.0           # * версия элемента, отдельно от passport_schema
role: ""                 # * одной фразой, зачем элемент в схеме
inputs:  []              # [{name, type, meaning}]
outputs: []              # [{name, type, meaning}]
depends_on: []           # [{id, version_range}]
must_not_touch: []       # чего элемент не меняет и не читает (без теста это заявление, а не гарантия)

links_in:                # что и от кого элемент принимает; всё остальное запрещено
  - from: <id>
    channel: ""          # mcp | down | up | side | ...
    format: ""           # что течёт
    mode: read           # read | write | read_write
    gate:                # мембрана; поля необязательны, но проверяемы
      accepts: []        # допустимые источники (определяет связь, а не сообщение)
      rate_limit: ""     # записей на источник за период
      min_score: {}      # порог по источнику: {<источник>: <число>}
      provenance_required: true

for_model:               # единственная часть, которую читает модель
  what: ""
  use_when: []
  do_not_use_when: []
  how_it_works: []       # простые утверждения: что хранит, что делает, чего не делает
  rules: {always: [], never: []}
  tools: []              # формат MCP: name, description, inputSchema, outputSchema, annotations + errors, examples
  resources: []          # формат MCP: uri, name, description, mimeType

contract:
  requires:
    - what: ""
      class: invariant   # invariant (всегда) | target (достигается со временем)
      status: done       # done | hypothesis | analogy | fantasy
      check: {test: "", metric: "", threshold: ""}   # порог записан до первого прогона
  bonus: []              # приятно, но в расчёт не берётся
  guarantees: []         # детерминизм, неизменяемость и т.п.
  known_losses: []       # известные потери, не скрытые баги

cost: {ram: "", time: ""}
droppable: {value: null, why: ""}   # можно ли убрать элемент, не тронув остальное
sources: []              # ссылки на материалы в AXMV2/
open_questions: []       # вопросы по этому элементу; общие вопросы проекта в Deferred
note: ""                 # свободный текст для человека, никому не передаётся
```

Правила для `for_model`:
- Ключи на английском, значения-описания пишутся для модели: коротко, плоско, утверждениями «да или нет», без «возможно» и градаций уверенности.
- Поля фиксированные, их пишет только пользователь (I18). Внешний текст в `for_model` не попадает.

Что видит агент:
- Агенту выдаётся проекция passport по белому списку полей, а не весь passport с вырезанным `note` (I7). Новое поле по умолчанию агенту невидимо.

Мембрана:
- Мембрана это `gate` внутри `links_in`. Поля обхода (`bypass`) в схеме нет, поэтому обойти мембрану нечем.
- Источник в `accepts` и `provenance_required` определяется идентичностью связи (`from`), которую выставляет транспорт, а не заявлением в самом сообщении (I16).
- Всё, чего нет в `links_in`, запрещено (`default: deny`).
- `links_in` объявляет принимающий элемент: граница и права записи принадлежат ему. `direction` убран: двусторонняя связь это две записи, каждую объявляет своя принимающая сторона.

### 2.1 kind

`kind` определяет, какие правила действуют по умолчанию. Остальное (ядро это или библиотека, можно ли убрать) задаётся другими полями, например `droppable`.

| kind | что это | что отличается по умолчанию |
|---|---|---|
| `code` | наш код и данные в дереве, включая «доски» | детерминирован; ядро или библиотека определяется `droppable` |
| `model` | локальная модель | недетерминирована; `cost` и «помещается в ноутбук» как `invariant`; остальное в основном `target` |
| `data` | паки, словари, константы | только `read`, неизменяема после загрузки; целостность по хешу, доверие отдельно |
| `external` | чужое, не в нашем дереве; passport это прокси | вход только через `gate` с `provenance_required`; содержимое не хешируется, только passport-прокси |
| `assembly` | корень сборки | члены находит скан; `inputs/outputs` нет |

Новый `kind` допустим, только если по умолчанию он отличается хотя бы одним правилом из таблицы. Иначе это значение другого поля или `code` со своим passport (I22).

## 3. Состояние (вычисляется, не хранится)

`state` считается из `status`, `contract` и `checks.yaml`. Результат проверки действителен, только если его `element_hash` равен текущему.

| state | условие |
|---|---|
| `stub` | нет `inputs` и `outputs` |
| `inhibited` | есть `invariant` с действующим результатом `failed`; либо `status: done`, а у какого-то `invariant` нет действующего `passed` |
| `training` | не `inhibited`, но какой-то `requires` без действующего `passed` |
| `connected` | все `requires` с действующим `passed` |

Условие `inhibited` для `status: done` без подтверждения принуждает статус быть честным: «сделано» без проверки считается нарушением. Не удаляет и не останавливает эксперимент (I13), только меняет `state`.

## 4. Проверки

```yaml
# checks.yaml (пишет только пользователь, I27)
element_hash: <хеш>
results:
  - test: ""
    metric: ""
    threshold: 50        # копия из контракта на момент прогона
    value: 0
    passed: true
    date: 2026-10-26
```

Порог в контракте записывается до прогона. Это то, что раньше называлось «числовой гейт»; слово `gate` теперь занято мембраной.

## 5. Хеш

- `element_hash = hash(каноническая форма passport.yaml + element_hash зависимостей)`.
- Каноническая форма: ключи отсортированы, UTF-8, без комментариев и без `note`, `open_questions`, `sources` (они меняются без смены обещаний).
- `checks.yaml` в хеш не входит.
- `assembly_hash = hash(отсортированные element_hash)`. Хранится в `index.yaml`.

## 6. Passport сборки

Тот же формат, что у элемента, `kind: assembly`.

```yaml
passport_schema: "0.2"
kind: assembly
status: hypothesis
version: 0.2.0
role: ""
compat: {passport_schema: ">=0.2 <0.3"}   # какие схемы принимает сборка
write_policy:
  allowed_writers: []     # кто вправе писать в память
  per_agent_spaces: true
change_policy:            # кто меняет passport
  # Для агента: запись или рекомендация агента (Deferred, журнал, open_questions, note)
  # не является согласованием и не даёт полномочий на правки (I28).
  # Агент правит passport только по прямой команде пользователя (I18).
  proposers: [user]
  advisors: [agents]
  approver: user
order: []                 # порядок запуска
```

Членов сборки в файле нет: их находит скан, список руками не ведётся (I1).

## 7. Версии

- Новая версия это полный снимок текущего решения. Предыдущая в неё входит, старые копии не хранятся.
- patch: правка без смены обещаний. minor: добавлено (поле, проверка). major: убрано или изменён смысл, нужна запись в `compat`.
- Журнал решений: одна строка на решение, без копий. Он отвечает на вопрос «почему так», а не «как было».

## 8. Журнал решений

- 0.2: `check.current` убран из контракта в `checks.yaml`. Причина: каждое измерение меняло `element_hash`, а результат привязан к хешу.
- 0.2: passport рядом с элементом, `genome.yaml` заменён генерируемым `index.yaml`. Причина: ручной список расходится с кодом.
- 0.2: `state` вычисляется, `status` остаётся только эпистемическим.
- 0.2: `agent_api` заменён `for_model` (что/когда/правила/tools в формате MCP).
- 0.2: `inputs`/`outputs` обязательны только при `status: done`. Причина: в v0.1 это противоречило допустимости стаба.
- 0.2: добавлен `change_policy` и два режима отказа (I12).
- 0.2: мембрана = `gate` внутри связи; обхода нет.
- 0.2: `gate-passed` из старой шкалы статусов стал результатом проверки с порогом, заданным до прогона.
- 0.2: `links_in` объявляет принимающий элемент; passport сборки и элемента один формат; `status: done` без подтверждённого результата даёт `inhibited`.
- 0.2: `kind` = набор правил по умолчанию: `code | model | data | external | assembly`. Причина: прежний список смешивал роль, форму и принадлежность, и значение не влекло последствий. `board` это `code` со своим passport.
- 0.2: порядок папок проекта (N9): `Invariants.md` в корне, спецификации в `specs/`, гайды в `guides/`, имена латиницей.
- 0.2: открытые вопросы вынесены в `Deferred.md` (I24). Причина: списки в нескольких файлах дублировались.
- 0.2: безопасность. Агенту выдаётся проекция по белому списку (чёрный список даёт утечку нового поля); источник в `gate` определяет связь, а не сообщение (иначе отравитель сам пишет нужный `source`); `checks.yaml` не пишут агенты (от него зависит `state`); запись агента в `Deferred` не даёт полномочий (иначе агент сам себе выдаёт права); область действия: работа над проектом исключение, правила для работы внутри модели (I26-I28).
